## Live cluster output (captured v0.1.2 — 2026-05-07 20:31 UTC)

The v0.1.0 binary failed at first live run with two real bugs surfaced by
the cluster:

1. Wrong Vault KV field name — read `value`, but the canonical field is
   `management_token` (matches the master plan's pre-flight pattern
   `vault kv get -field=management_token …`). Fixed in v0.1.1.
2. CA bundle's intermediate was being treated as a root in `CustomTrustStore`,
   yielding `PartialChain`. Per memory `feedback_smoke_gate_probe_robustness.md`,
   intermediates have to go to `ExtraStore`. Bundle now split on
   `Subject == Issuer`. Fixed in v0.1.2.

After both fixes the CLI runs cleanly against the live 0.E.4 cluster.

### Setup that produced the output below

```pwsh
$env:VAULT_ADDR    = 'https://192.168.70.121:8200'
$env:VAULT_CACERT  = "$HOME\.nexus\vault-ca-bundle.crt"
$env:VAULT_TOKEN   = '<from vault login -method=ldap>'

# Override defaults to use the VMnet10 cluster backplane (the cert covers both
# 192.168.10.x and 192.168.70.x but the cluster's own discovery uses .10.x).
$env:NEXUS_CONSUL_ADDR    = 'https://192.168.10.111:8501'
$env:NEXUS_NOMAD_ADDR     = 'https://192.168.10.111:4646'
$env:NEXUS_PORTAINER_ADDR = 'https://192.168.10.111:9443'
```

**As of `nexus-infra-swarm-nomad` v0.1.1 (Phase 0.E.4e, 2026-05-08), the
bundle-augmentation workaround is RETIRED.** The cluster now serves the
full chain (leaf + intermediate) on every TLS handshake, so the stock
root-only `vault-ca-bundle.crt` from Phase 0.D.2 is sufficient on its own.

**For runs against a cluster at v0.1.0 (pre-0.E.4e), the workaround was:**

```pwsh
# Append the NexusPlatform Intermediate CA to the build-host bundle
$resp = Invoke-RestMethod -SkipCertificateCheck `
  -Uri "https://192.168.70.121:8200/v1/pki_int/cert/ca" `
  -Headers @{ 'X-Vault-Token' = $env:VAULT_TOKEN }
Add-Content -Path "$HOME\.nexus\vault-ca-bundle.crt" -Value "`n$($resp.data.certificate)"
```

This is no longer required against a cluster at v0.1.1 or later. See
[ADR-0019](https://github.com/grezap/nexus-platform-plan/blob/main/docs/adr/ADR-0019-tls-fullchain-on-wire.md)
+ [`nexus-infra-swarm-nomad/docs/verification/0.E.4e-cold-rebuild.md`](https://github.com/grezap/nexus-infra-swarm-nomad/blob/main/docs/verification/0.E.4e-cold-rebuild.md)
for the full-chain rendering decision + the cold-rebuild proof.

## What remains deferred

- **Live cluster output from a Linux operator host.** CI builds the
  linux-x64 artifact and asserts the size budget, but interactive smoke
  against the cluster from a Linux box is deferred until that operator
  workstation exists.
- **Cluster-side full-chain fix** for Consul / Nomad / Portainer TLS
  servers. Tracked as a follow-up task; once it lands, this doc's bundle-
  augmentation step can be retired.
- **Portainer reachability + status.** Out of scope for v0.1.x; pairs with
  the cluster-side fix above.
- **`●` glyph rendering on Windows pwsh.** Aesthetic only; v0.2 will set
  `[Console]::OutputEncoding = [System.Text.Encoding]::UTF8` at process
  start so Spectre's status emojis render correctly out of the box.
