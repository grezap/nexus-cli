## Destructive smoke — `suspend` → `status` → `resume` round-trip on `foundation/vault-3`

This is the master-plan-acceptance proof that the write verbs work end-to-end
against the live cluster. Vault Raft retains quorum on `vault-1` + `vault-2`
during the suspend window so the cluster stays unsealed and serves; vault-3
returns to a running state at the end.

```text
> nexus.exe infrastructure status foundation --node vault-3
── foundation / vault-3 · 1 VMs ──────────────────────────────────────
| Name    | State   | OS    | VMnet10        | VMX                                            |
| vault-3 | running | deb13 | 192.168.10.123 | H:\VMS\NexusPlatform\01-foundation\vault-3\vault-3.vmx |
exit=0

> nexus.exe infrastructure suspend foundation --node vault-3 --yes
── suspend · foundation · 1 VMs ──────────────────────────────────────
  ✓ vault-3                suspended
exit=0

> nexus.exe infrastructure status foundation --node vault-3
── foundation / vault-3 · 1 VMs ──────────────────────────────────────
| Name    | State   | OS    | VMnet10        | VMX                                            |
| vault-3 | stopped | deb13 | 192.168.10.123 | H:\VMS\NexusPlatform\01-foundation\vault-3\vault-3.vmx |
exit=0

> nexus.exe infrastructure resume foundation --node vault-3 --yes
── resume · foundation · 1 VMs ───────────────────────────────────────
  ✓ vault-3                resumed
exit=0

> nexus.exe infrastructure status foundation --node vault-3
── foundation / vault-3 · 1 VMs ──────────────────────────────────────
| Name    | State   | OS    | VMnet10        | VMX                                            |
| vault-3 | running | deb13 | 192.168.10.123 | H:\VMS\NexusPlatform\01-foundation\vault-3\vault-3.vmx |
exit=0
```

The post-suspend `status` row reads `stopped` rather than `suspended` because
the VMware Workstation Pro version on the build host doesn't emit a `.vmss`
sidecar next to the `.vmx` after a clean `vmrun suspend`; the heuristic in
`InfrastructureService.ClassifyState` looks for that file. **Functionally the
suspend/resume cycle works correctly** (RAM state preserved, no boot-from-cold
on resume, full round-trip exits 0 every step). The label refinement is
deferred to v0.2.x — see CHANGELOG.

## Negative paths

| Case | Result |
|---|---|
| `vault-3` already suspended; second `suspend --yes` invocation | exit 0; per-VM message `already stopped` (heuristic limitation) |
| `nexus infrastructure suspend foundation --node ghost` | exit 2; `unknown node 'ghost' in cluster 'foundation'. Known: …` |
| `nexus infrastructure suspend foundation` (interactive shell, declined) | Confirm prompt defaults to *no*; pressing Enter aborts with exit 3 + `aborted by user.` |
| `echo n \| nexus infrastructure suspend foundation` (stdin redirected) | exit 3; `aborted: suspend of foundation requires interactive confirmation; pass --yes for non-interactive use.` |
| Linux build host invocation (cross-compiled binary) | `list` works catalog-only (every state renders `unknown`); `status`/`suspend`/`resume` exit 2 with `vmrun.exe is Windows-only; this command requires the win-x64 build host.` |
| `nexus.exe` invoked with `vmrun.exe` renamed away | exit 2; `vmrun.exe not found. Install VMware Workstation Pro or set NEXUS_VMRUN_PATH.` |

## What remains deferred

- **Spectre.Console.Cli 0.55 bump.** Breaking change in `AsyncCommand<T>.ExecuteAsync`
  (gains a `CancellationToken` parameter); touches all 6 commands. Deferred
  to v0.2.x to keep this tag's diff focused on the new verb.
- **Suspended-vs-stopped state inference.** Current heuristic
  (`File.Exists(<vmx>.vmss)`) doesn't trigger on Workstation Pro 17.5+;
  post-suspend status renders `stopped`. Functional behaviour is correct.
  Tracked for v0.2.x — likely solved by extending the sidecar check to
  `.vmem`/`.vmsd`/`.vmsn` or by calling `vmrun checkPowerState`.
- **Linux runtime probing.** `list` works catalog-only; `status`/`suspend`/`resume`
  exit 2. Unblocks when a Linux operator workstation is added to the fleet.
- **`winget` manifest + `.deb` packaging.** Tracked in roadmap; not part of v0.2 scope.
- **`--watch` flag** for `list` and `status`. Out of v0.2 scope.
