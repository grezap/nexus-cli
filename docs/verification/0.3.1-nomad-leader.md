## v0.3.0 CI failure rolled into this tag

`release.yml` for v0.3.0 failed on both linux-x64 + win-x64 runners:

```text
Failed Nexus.Cli.Tests.Ssh.SshKeyDiscoveryTests
      .Resolve_Falls_Through_When_Env_Var_Points_At_Missing_File
  Expected string that does not start with '/tmp/', but found <null>.
```

Cause: CI runners have no `~/.ssh/id_*`, so `SshKeyDiscovery.Resolve()`
returns `null`, and FluentAssertions' `NotStartWith` errors on null.

Fix (commit `4ff53ae` in this slice): guard the `NotStartWith`
assertion behind a `null` check. The preceding line already asserts
the value is either null OR an existing file; this commit only refines
the path-validation step to skip when the fallback found nothing.

The v0.3.0 git tag remains on origin pointing at `ae5c4a9` (with no
GitHub Release object); v0.3.1 supersedes it. Operator chose this
path over retagging to minimise destructive remote tag operations.
