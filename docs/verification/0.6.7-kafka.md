## Auth-model decision (from a live probe)

Kafka is **mTLS-only** — `server.properties` carries `ssl.client.auth=required` and *no* SASL/password.
So, like Redis, there is **no `INexusVaultClient` and no operator password**: the operator identity is
the broker's own Vault-PKI keystore. Every CLI runs ON a broker via
`sudo /opt/kafka/bin/kafka-*.sh --command-config /etc/nexus-kafka/client-ssl.properties`, bootstrapped at
`SSL://<vmnet10>:9092` (the VMnet10 backplane IP is in the broker cert SAN, which
`ssl.endpoint.identification.algorithm=https` requires). `sudo` is needed because `/etc/nexus-kafka` is
`0750 root:kafka`.

## Control surface (ADR-0018)

- **Per-cluster (kafka-east / kafka-west):** `kafka-metadata-quorum describe --status/--replication`
  (controller leader + voters + per-voter LEO/lag), `kafka-topics --describe` (partitions/RF/ISR),
  `kafka-acls` (the StandardAuthorizer), `kafka-console-{producer,consumer}` (backup round-trip),
  `pki_int/issue/kafka-broker` + `kafka-tls-split.sh` (cert-rotate), `nexus-chaos.sh` (chaos).
- **Ecosystem:** `systemctl is-active <unit>` + each service's HTTPS health endpoint
  (SR :8081 `/subjects`, REST :8082 `/v3/clusters`, Connect :8083 `/`, ksqlDB :8088 `/healthcheck`) +
  the MM2 journal.

## ACL enforcement (decision 4)

`role-overlay-kafka-acl-authorizer.tf` appended `authorizer.class.name=…StandardAuthorizer` +
`super.users=<15 platform principals>` + `allow.everyone.if.no.acl.found=false` to every broker and
rolling-restarted (followers first, leader last — not a big-bang; the SSL listeners are unchanged so the
quorum keeps a leader). `super.users` lists **all 6 brokers + all 9 ecosystem nodes** on both clusters —
every node that connects to a broker authenticates with its own cert (`User:CN=<host>.kafka.nexus.lab`),
and the ecosystem services are Kafka clients, so omitting them would have deny-by-default broken the
running platform. Ordinary application principals stay deny-by-default, which is what makes `acl grant`
meaningful. Validated on a single follower canary (east-3) before the full roll.

## Bugs caught by live-verify

**None.** All verbs went green against both clusters + the ecosystem on the first live invocation. The
thorough up-front contract probe pre-empted the usual 1–4: the `--consumer.config` vs `--command-config`
flag split (caught before the backup verb shipped), the real Connect/ksqlDB ports (8083/8088, not the
scoping note's 8088/8090), the `super.users`-must-include-ecosystem design, and the VMnet10-SAN bootstrap
requirement. Same outcome as the StarRocks slice — careful infra reading beats live debugging.
