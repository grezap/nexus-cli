## Auth-model decision (from a live probe)

keyFile-only internal auth, **no TLS on the wire** in 0.N v1 (mTLS is the deferred 0.N.1 hardening,
ADR-0040), `authorization=enabled`. The cluster's single secret is the keyFile (Vault KV
`nexus/oltp/mongo/keyfile`, field `content`; on every node at `/etc/nexus-mongo/keyfile`). Two-headed
auth, both using the keyFile content as the password:

1. **Direct mongod RS ops** (config + shards) — `__system`@`local` (SCRAM-SHA-256) on `127.0.0.1:<rs-port>`.
   This is the ONLY principal the **shard** mongods accept (`nexus-sharded-admin` was created only on the
   config-server RS — confirmed live: a shard 27018 rejects it with `Authentication failed`).
2. **Cluster-level ops** (sh.status, balancer, config metadata, ACL, backup) — `nexus-sharded-admin`@`admin`
   **through a mongos** (`127.0.0.1:27017`). `__system`/`local` is rejected through mongos
   (*"Can't use 'local' database through mongos"*).

## Live-caught bug (the lesson)

**`HealthAsync` mongos-JS single-quote collision.** The cluster-level health query used single-quoted JS
string literals (`db.getSiblingDB('config')`, `'SHARDS='`), which terminate the outer `--eval '...'`
shell quoting early → the `shards-registered` probe reported red ("unreachable via mongos") even though
the routers were alive. **Fixed** to double-quoted JS literals (`\"config\"`, `\"SHARDS=\"`), matching
the convention every other verb already follows. Re-verified green. Every other verb was first-try-green —
the up-front contract probe (the two-headed auth, the shard-mongod `__system`-only finding, the no-TLS
contract, the mongos-can't-use-local rule) pre-empted the rest of the usual 1–4.
