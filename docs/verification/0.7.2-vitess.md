## Auth-model decision (from a live probe) — hybrid

- **gRPC control plane** (status / topology / failover / scale-out / backup-orchestration): the
  mTLS-preloaded wrapper `sudo /usr/local/sbin/nexus-vtctldclient` on the control node — **no password**
  (the node's per-host PKI leaf is the credential). Tablets report their **VMnet10** IP in the topo,
  mapped back to a node via vms.yaml.
- **SQL plane** (health write-probe + sharding proof): the vtgate `:15306` MySQL listener over **mTLS**
  as the static-auth user `nexus`, run from a tablet node (`mysql` client + TLS leaf), connecting to a
  vtgate vmnet11 (`--ssl-mode=REQUIRED --ssl-cert/key/ca`, the listener requires a client cert). Password
  = the app password in Vault KV `nexus/vitess/mysql-app-password` (field `content`); `mysqldump` uses
  `vt_dba` (`nexus/vitess/mysql-allprivs-password`). Both via `INexusVaultClient` (ADR-0011 model).

Two findings that shaped the build: **no Vitess BackupStorage backend** is configured in 0.O
(`GetBackups` → "no registered implementation of BackupStorage"; no xtrabackup) → backup is a logical
`mysqldump` round-trip; and **`CREATE USER` via vtgate fails** ("syntax error near 'USER'") → acl manages
the vtgate static-auth file, not SQL DDL.

## Live-caught bugs (3 — the lessons)

1. **etcd-quorum health probe always red.** The `nexus-etcdctl` wrapper carries all 3 endpoints, so one
   `endpoint health` reports the whole cluster (3 "healthy" lines), not 1 per node — the per-node
   `StartsWith('1')` count failed. **Fixed:** run once, count `"is healthy"` lines (NOT bare `healthy`,
   which also matches `unhealthy`). health → green, etcd 3/3.
2. **`mysqldump commerce` → "Unknown database 'commerce'".** Vitess names the underlying mysqld database
   **`vt_commerce`** (the keyspace prefixed with `vt_`); vtgate translates the keyspace name but DIRECT
   mysqld access must use `vt_commerce`. **Fixed** the dump source db; backup take + restore round-trip green.
3. **chaos on a PRIMARY rejected by systemd.** `nexus-chaos.sh process-kill` SIGSTOPs a *single* unit; the
   primary path passed two space-separated units → "Unit nexus-vttablet\x20nexus-mysqlctld.service not
   loaded". **Fixed** to a single unit — freeze `nexus-mysqlctld` (mysqld) on a primary (which is exactly
   what triggers VTOrc auto-reparent), `nexus-vttablet` on a replica. Re-verified: VTOrc reparented `80-`.

The other verbs were first-try-green — the up-front contract probe (the hybrid auth split, the VMnet10
topo mapping, the no-BackupStorage finding, the CREATE-USER-via-vtgate finding) pre-empted the rest.

## How to reproduce

```pwsh
# env: VAULT_ADDR/TOKEN/CACERT + NEXUS_SSH_KEY/USER + NEXUS_VMS_YAML (see README / scratch/nx.ps1)
nexus status   vitess
nexus health   vitess
nexus topology vitess
nexus failover-test cluster vitess --yes
nexus scale-out remove vitess vitess-shard2-tablet-3 --yes
nexus scale-out add    vitess --role replica --shard 80- --yes
nexus backup take    vitess --yes
nexus backup restore vitess <backup-id> --yes
nexus cert-rotate vitess --yes
nexus acl vitess list
nexus chaos vitess process-kill --yes                              # replica
nexus chaos vitess process-kill --target vitess-shard2-tablet-1 --yes   # primary -> VTOrc reparent
```

Prerequisite: the 12 `vitess` VMs powered on (foundation base + the cluster). Bring-up + the cluster
cold-rebuild are in `nexus-infra-vitess` (handbook §0-§3.1; `scripts/vitess.ps1`).
