## Tier state at verify time (the headline finding)

The tier was found in a **post-v0.8.1-Vault-greenfield broken-trust state** (it was OFFLINE during that 2026-06-18/19 rebuild — the same casualty class as the swarm tier's Portainer drift). Three infra divergences, all surfaced by the diagnose-first probe and reported honestly by the adapter (none is an adapter bug):

1. **vault-agent broken trust (tier-wide).** The obs node leaves were issued **2026-05-26 by the OLD "NexusPlatform Root CA"**; the build host's current `vault-ca-bundle.crt` root is the **NEW** root (notBefore 2026-06-19, same CN/different key). The on-node `nexus-vault-agent`s can't re-authenticate (their `ca-bundle.crt` trusts the old root) → no token at `/var/run/nexus-vault-agent/token`, and the build-host CA bundle cannot validate the obs leaves. **This drove the access posture: SSH-local-curl with each node's own `ca.crt`** (always self-consistent) instead of build-host HTTP.
2. **Grafana admin password drift.** The greenfield rotated KV `nexus/observability/grafana/admin-password`; the live Grafana (admin in the shared PG) still holds the pre-greenfield value → admin API 401.
3. **grafana-pg replication split.** grafana-pg-2 was promoted during the 0.I.4 `-Strict` failover test (2026-05-27) and never re-seeded (no `standby.signal`) → both nodes run as primary; Grafana uses pg-1 via VIP .185.

**The clean repair is a Greg-authorized tier trust re-apply** (`observability.ps1`: re-bootstrap the vault-agents vs the new root → re-issue certs → reconcile the Grafana admin password → re-seed the pg standby via `smoke-0.I.4.ps1 -Strict`), mirroring the swarm tier's post-greenfield cold-rebuild. An autonomous grafana-pg standby re-seed was (correctly) policy-denied this session — "diagnose + build the adapter, not repair the cluster."

## Cold-rebuild proof (2026-06-22; operator-authorized)

`observability.ps1` per-sub-phase destroy (otel/grafana/tempo/loki/prom — 14 VMs + overlays) → `all`/per-sub-phase apply from zero, onto the **new** Vault root (the `vmrun_path` x86→non-x86 trap was fixed in all 5 obs envs + `modules/vm` first; the build-host obs vault-agent sidecars — regenerated by the greenfield on Jun 19 — were verified to AppRole-login against the new Vault before the rebuild). The rebuild **fixed all three divergences**: every rebuilt node's vault-agent re-authed + rendered new-root certs (trust); the grafana-pg replication overlay re-seeded pg-2 (`1 streaming standby`, green); Grafana re-initialised its admin from the current KV (auth works).

**Transients / cross-tier findings chronicled:**
- **prom smoke warmup (T-class):** `0.I.1` failed once on `≥2 prometheus job targets up` immediately post-start (pre-first-scrape) → passed on re-run. Tempo `/ready` similarly 503s until S3+ring warm.
- **grafana HA migration-lock race:** both active-active Grafanas raced the shared-PG migration on first start (`Failed to lock database`) → fixed by a sequential restart.
- **THE cross-tier CA-generation split (the headline rebuild finding):** loki/tempo (rebuilt → new-root) could not TLS to their S3 backend **MinIO** (`minio.nexus.lab`, lakehouse tier, NOT rebuilt → still old-root) → `x509: certificate signed by unknown authority`. Resolved by **re-certing the 4 MinIO nodes to new-root** (push the fresh Jun-19 sidecars + new-root ca-bundle + force the `pkiCert` re-render; **big-bang restart all 4** — a rolling one-node re-cert breaks the distributed cluster's inter-node mTLS, like the Nomad-parallel lesson). MinIO reformed on new-root (`/minio/health/cluster` 200 ×4).
- **MinIO IAM key drift (next layer):** loki/tempo then hit `InvalidAccessKeyId (403)` — the greenfield rotated KV `observability/{loki,tempo}/s3-{access,secret}-key`, but MinIO's `nexus-loki-app`/`nexus-tempo-app` users held the old keys → re-synced via the obs-tenants `mc admin user add` logic with the current KV keys (the existing `nexuslocal` mc alias still authenticated even though the KV **root** creds had also drifted — a noted, non-blocking finding). loki + tempo then came up `3/3` ready.
- After the above, **`nexus health observability` is ALL GREEN** and the **full verb matrix re-ran green** (failover grafana RTO 1.2 s + grafana-db RTO 1.4 s; scale-out loki ring; chaos process-kill recovered; cert-rotate 12 nodes new serials; acl list via `/api/org/users`; backup N/A).
- **Platform note:** this proves the obs tier cold-rebuilds cleanly to the new root, but it surfaced that the v0.8.1 greenfield left a **platform-wide CA + credential split** — every still-old-root tier (the rest of lakehouse: Spark/Nessie/Iceberg-pg/ZK; kafka; oltp; analytics; harbor) will need the same new-root re-cert + KV-cred reconcile on its next bring-up. The fresh Jun-19 sidecars make each tier's rollover mechanical (push sidecar + new ca-bundle → re-auth → re-render).
