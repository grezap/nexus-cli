## Tier state at verify time (the headline finding)

The tier was found in the **post-v0.8.1-Vault-greenfield casualty class** (it was OFFLINE during that 2026-06-18/19 rebuild — the same class the observability tier hit, ADR-0024). Diagnosed first (none is an adapter bug):

1. **Cross-tier CA-generation split.** MinIO was re-certed to the NEW Vault root in the v0.8.3 session (leaf notBefore 2026-06-22; vault-agent re-authed) and is fully GREEN. But **Nessie + iceberg-pg + Spark + ZooKeeper were STILL on the OLD root** (leaf notBefore 2026-05-23; vault-agent token absent → can't re-auth to the new Vault). So old-root Nessie's JVM truststore could not validate the new-root MinIO S3 leaf (`PKIX path validation failed: Path does not chain with any of the trust anchors`) → Nessie `/q/health` reported the "Warehouses Object Stores" check DOWN. Nessie's DB check (→ old-root iceberg-pg) was UP.
2. **iceberg-pg replication split.** iceberg-pg-1 = primary (`pg_is_in_recovery=false`) with `pg_stat_replication` count 0; iceberg-pg-2 ALSO primary (never re-seeded as a standby). VIP `.151` on pg-1. `health` correctly RED.

**The clean repair is a Greg-authorized cold-rebuild of the Iceberg + Spark envs only** (MinIO kept in place — reformatting its EC drives would wipe the four cross-tier buckets it serves: observability `loki`/`tempo`, registry `harbor`, analytics `starrocks`). The fresh new-root Iceberg/Spark certs trust the live new-root MinIO → CA split + pg split resolved.

## Cold-rebuild (Iceberg + Spark envs; MinIO kept) — transients chronicled

Pre-flight: fixed `vmrun_path` x86→non-x86 in `terraform/envs/lakehouse-{iceberg,spark,minio}/variables.tf` + `terraform/modules/vm/variables.tf` (the stale-path trap). The Jun-19 build-host vault-agent sidecars are new-root (the mechanical re-cert path).

1. **vmrun "Unknown error"** (T1, [[feedback_vmrun_unknown_error_transient]]) — `iceberg-rest-1.power_on` hit the sporadic rc=1 after destroy (the other 3 powered on fine); re-running apply retried the tainted power_on clean.
2. **Post-destroy zombie VMs** (T2, the v0.8.1 class) — the iceberg destroy ran with the pre-fix x86 path still in state, so the clone_vm destroy-provisioner's `& <x86-vmrun> stop` failed (binary gone; non-terminating) and left the 4 iceberg VMs RUNNING with their dirs intact (`vmrun stop` by .vmx then 404s — the .vmx is detached). Recovered via **in-guest `systemctl poweroff`** of the 4 VMs → wait for power-off → `Remove-Item` the dirs → apply clones fresh. (The rebuilt state bakes the non-x86 path, so future destroys won't zombie.)
3. **MinIO IAM key drift → S3 403** (T3, the obs-precedent IAM re-sync) — fresh new-root Nessie cleared the CA split (the PKIX error was gone) but then hit `S3Exception: Forbidden (403)` on the warehouse object store: the greenfield had rotated KV `lakehouse/minio/app-secret-key` while MinIO's `nexus-lakehouse-app` user kept the old secret → SignatureDoesNotMatch. Fixed (Greg-consented, data-preserving) by resetting **only** that user's secret to the current KV value on-node (`mc admin user add nexuslocal nexus-lakehouse-app <kv-secret>`, secret read + used via minio-1's own vault-agent token — never crossing the transcript); the access key + `readwrite` policy + all bucket data unchanged. Nessie S3 403 → 200.

**Live-caught bug #1 (cert-rotate; fixed in source):** the first `cert-rotate` run reported Spark nodes as `(jvm-truststore)` with "vault-agent re-render did not confirm". Root cause = Spark/ZooKeeper have an **empty `TlsDir`**, so the force-rerender witness path resolved to a bogus `/bundle.pem`. The real contract (diagnosed live): **Spark has no rotatable server leaf** — its RPC is shared-secret + AES (`spark.authenticate` / `spark.network.crypto`) and its only on-node trust material is the JVM truststore CA (the vault-agent renders `ca-bundle.crt`, not a per-node leaf); **ZooKeeper is backplane-only plaintext** (ADR-0035; no TLS, no vault-agent at all). Fixed → both return a graceful **N/A** row with the right reason (mirroring the iceberg-pg DR-runbook deferral) instead of attempting a re-render. cert-rotate dropped from 229 s → 31 s (no pointless Spark/ZK restarts).

**Live-caught bug #2 (iceberg-pg failover → graceful N/A; fixed in source):** the as-is `--direction iceberg-pg` VRRP cutover appeared to succeed (VIP `.151` moved, RTO ≈ 1.4 s) but it **left the tier degraded** — the keepalived `notify_master` hook **promoted the standby** (iceberg-pg-2 → `in_recovery=f`) while `nopreempt` left the old primary (iceberg-pg-1) un-demoted → **split-brain (both nodes primary)**, and the promoted standby's `pg_hba.conf` did not admit the Nessie REST hosts (`no pg_hba.conf entry for host 192.168.70.147, user nessie`) → **Nessie crash-looped** (Agroal JDBC failures, restart counter 31). A keepalived VRRP cutover of a PG primary/standby pair is **not a safe adapter one-shot** — a correct catalog-DB failover is a coordinated DR runbook (promote new + demote/fence old + `pg_basebackup` re-seed), the same call the obs adapter made for grafana-db. **Fixed → `--direction iceberg-pg` returns a graceful actionable N/A** explaining the split-brain risk and routing to `--direction spark-master` (the live-proven HA drill). **Tier restored** (a side-effect of the diagnostic): moved the VIP back to iceberg-pg-1 (stop keepalived on pg-2 → the `.151` VIP returns to the higher-priority primary) → restarted Nessie → re-seeded iceberg-pg-2 as a streaming standby via the sanctioned overlay (`terraform taint null_resource.iceberg_pg_replication` + targeted apply → `pg_basebackup -R`, "streaming standby count=1"). `health lakehouse` → overall GREEN again.

**Transient observed (not a bug):** running `status`/`health` immediately after `cert-rotate` briefly shows the two Nessie nodes `failed` — `cert-rotate` restarts `nexus-nessie` and Quarkus + S3 init takes a few minutes to return `/q/health` 200. Let Nessie settle after a cert-rotate before the next read verb.
