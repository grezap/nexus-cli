## Batch 3 — `scale-up` (#13) · swarm restore (#11) · kafka resize-gate (#4)

### `scale-up` / `VmrunVmResizer` (GAP #13 — skeleton → full verb)
- CPU/RAM: `vmrun stop` → atomic `.vmx` edit (`numvcpus`/`memsize`) → **cold** start. Disk: `vmware-vdiskmanager -x` grow + a **SAFE** in-guest FS extend (`growpart --dry-run` gated; LVM + plain-partition + Windows; **never repartitions a live boot disk**).
- **Cluster-safety gate:** resolves the owning adapter (`ResolveOwningAdapterId` — 1:1 + the splits `sqlserver`/`sqlserver-ag`, `foundation`→`vault`/`foundation-ad`, `platform-tools`→`registry`; edge/workstations skip), warms its status, consults `CanResizeVm`; **refuses the current write-primary** (or an unreachable cluster) unless `--force-primary`.
- New `IVmrunClient.StopAsync`/`StartAsync`/`GrowVirtualDiskAsync`; `VmrunPaths.ResolveVdiskManager()`; `BuildVmResizer` wires `ISshClient`.
- **Live-verified on redis-1:** cpu 2→4 + ram 2048→3072, then a scale-DOWN 4→2 / 3072→2048 (guest `nproc`=4, MemTotal ~3 GB); disk 40→42 GB vmdk grow — guest `lsblk` confirms the larger disk, and `growpart --dry-run` correctly detected the **deb13 root-not-last** layout → honest "not auto-extended" warning (`Outcome ok`, no false success).

### swarm guarded `backup restore` (GAP #11)
- Real restore behind an explicit **`--confirm-destructive`** (on top of `--yes`; `RestoreRequest.ConfirmDestructive`): uploads `consul.snap`/`nomad.snap` to a manager, runs `consul snapshot restore` + `nomad operator snapshot restore` online against the leader, counts restored KV keys + jobs. Refuses without the flag (points at the DR runbook).
- **Live-verified on the swarm tier:** the guard refuses without the flag; with it, restoring a just-taken snapshot runs GREEN. (Recovering the tier surfaced a Consul `server_rejoin_age_max` >7-day-off freeze — fixed non-destructively; then baked into the swarm consul template.)

### kafka resize-gate (GAP #4)
- The meta `KafkaAdapter` delegates `CanResizeVm` to the per-region adapters; `KafkaClusterAdapter` gates on the **controller-leader** (`Role != "controller-leader"`, needs a warmed status). `scale-up` resolves a broker VM to its region adapter (`kafka-east-1` → `kafka-east`).
- **Live-verified on kafka-east:** `scale-up` the controller-leader (kafka-east-1) is refused ("…pass --force-primary"); a follower passes the gate. Locked with a resolution unit test.
