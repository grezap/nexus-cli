## The mechanism

Both `grafana-pg` (obs, VRRP VIP `.185`) and `iceberg-pg` (lakehouse, VRRP VIP `.151`) are a 2-node
PG 17 streaming-replication pair whose TLS leaf is rendered by each node's own `nexus-vault-agent`
(`pkiCert` → `bundle.pem`, post-render split into `server.crt`/`server.key`).

`PgSslCertRotator.RotatePairAsync`:
1. Resolves the **primary** — the node where `pg_is_in_recovery()` returns `f`.
2. Orders **STANDBY-FIRST, primary LAST** (`OrderStandbyFirst`, unit-tested).
3. Per node: force the vault-agent to re-issue (back up + `rm` `bundle.pem` — `pkiCert` reuses the leaf
   otherwise — → `systemctl restart nexus-vault-agent` → poll the re-render → restore the `.bak`), then
   **`systemctl reload postgresql@17-main`** — a **SIGHUP, not a restart**. PostgreSQL re-reads
   `ssl_cert_file`/`ssl_key_file` for NEW connections while existing sessions (including the
   streaming-replication connection) keep running, so replication is never dropped.
4. **Safety:** if a standby's rotation fails, the primary is left untouched (rotating the sole-serving
   primary blind is exactly what standby-first avoids). A same-serial result is surfaced (the agent
   reused the cached leaf) rather than reported as a rotation.

## Live verification (2026-07-07, on the real nodes)

Powered on base (vault + gateway) + the two PG pairs only (4 VMs; minimal running). The identical shell
the adapter runs was executed node-by-node.

### iceberg-pg — the clean 1-primary + 1-standby proof
| node | role | old serial | new serial | after |
|---|---|---|---|---|
| iceberg-pg-2 (.150) | **standby** (rotated FIRST) | `1833…D15C` | `2992…2579` | still standby; primary sees `192.168.10.150 \| streaming` |

**Both leaves rotated; PG reloaded (no restart); streaming replication survived both rotations.** This is
the standby-first contract proven end-to-end.
