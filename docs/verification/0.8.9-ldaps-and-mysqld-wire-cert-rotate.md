## GAP #9 — FoundationAD DC LDAPS cert-rotate

Was a graceful "the security overlay does it" skip. Now `RotateCertAsync` rotates each DC's LDAPS leaf,
**STANDBY DC FIRST then the PDC** — a botched standby rotation aborts before touching the PDC's auth plane.

Per DC:
1. Issue the leaf + build the PFX **on vault-1 with openssl** — the proven Schannel path (a .NET-exported
   PFX lands ephemeral in MachineKeys and NTDS resets every handshake, the overlay's hard-won lesson).
2. SFTP the PFX + intermediate + root to the DC (Windows OpenSSH `/C:/…` form).
3. Import **root→LocalMachine\Root, intermediate→CA, leaf→My** (all three load-bearing — without the root
   locally, Schannel logs Event 36886 and resets every LDAPS handshake), verify the chain builds.
4. **`Restart-Service NTDS` + re-cycle ADWS** — all in ONE SSH session. `sshd` is independent of NTDS, so
   the established session survives the ~20-30 s restart; there is NO new SSH auth during the outage, so
   the #10 self-fence (which needed a new connection while NTDS was down) cannot occur. ADWS comes back
   from an NTDS restart in a state that fails `Get-AD*` with "bad parameter" (the adapter's own status/
   health verbs use `Get-AD*`), so a clean ADWS restart is folded in.
5. **Verify the :636 handshake from the build host** (a fresh TCP+TLS socket — no SSH), returning the
   served cert's serial as the new serial (proves LDAPS actually serves the new leaf).

Reads `VAULT_TOKEN` (issue) + `VAULT_CACERT` (root CA). `ParseIssueJson` unit-tested.

## GAP #12 — Vitess tablet mysqld-wire cert-rotate

Was `nexus-vttablet`-only ("mysqld-wire reload deferred"). Two fixes:

1. **mysqld-wire reload:** the tablet's mysqld serves the wire cert on :3306 (replication + vt_dba +
   vtgate→mysqld). After the leaf is re-rendered, mysqld reloads it **online via `ALTER INSTANCE RELOAD
   TLS`** (Percona 8.4) — no restart, **no reparent**, the PRIMARY is never demoted. (The memory
   anticipated a PRS→restart→reparent; the online reload is strictly better.)
2. **Durability fix (pre-existing bug the verify surfaced):** the old approach issued via the node's
   agent token + wrote `bundle.pem` directly — which the vault-agent's next render silently reverted
   (`pkiCert` reuses its cached leaf), so the entire vitess cert-rotate (gRPC included) was non-durable.
   Switched to **forcing the agent to re-issue** (rm `bundle.pem` → restart the agent → its post-render
   split writes a fresh leaf that persists), the Swarm/obs/lakehouse pattern. `ParseRerender` unit-tested.
