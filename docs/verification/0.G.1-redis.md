## What shipped

`RedisAdapter` (`src/Nexus.Cli.Adapters/Cluster/RedisAdapter.cs`) implements all of
`IClusterAdapter` via SSH-shell-out to on-node `redis-cli` (no managed Redis driver). The
v0.6.0 work both **finished the 5 stubbed verbs** (scale-out add/remove, backup take/restore,
chaos) AND **fixed three bugs that only a live cluster could surface** (below). Registered in
`ClusterBootstrapper`. Chaos uses an embedded on-node helper (`Cluster/Resources/nexus-chaos.sh`).

## The connection contract — corrected against the live cluster

The framework-ship adapter was **code-complete but wrong against the real cluster** on three
counts (all fixed in v0.6.0). This is the headline lesson: live-verify catches what unit tests cannot.

| Adapter assumed | Live reality (`/etc/nexus-redis/redis.conf`) | Fix |
|---|---|---|
| `REDISCLI_AUTH=$(cat …/auth-password.txt)` | `port 0` + `tls-port 6379` + `tls-auth-clients yes` ⇒ **mTLS-only, no password** (`default … nopass`) | drop AUTH; pass `--cert`/`--key` |
| `--cacert …/ca.pem` | the CA file is **`ca.crt`** | use `ca.crt` |
| unit `redis-server` | stock unit is **masked**; the cluster runs under **`nexus-redis`** | target `nexus-redis` |

Correct invocation: `sudo redis-cli --tls --cacert ca.crt --cert server.crt --key server.key …`.

## Bugs caught + fixed by live-verify

1. **`status`/`health`/`topology`/`acl` all returned nothing** — the connection contract above.
2. **`failover` reported "original primary: unknown"** — a hostname-index heuristic that breaks
   once roles move. Fixed: resolve the original primary from the replica's live `INFO replication`
   `master_host`.
3. **`cert-rotate` did not rotate** — the Vault Agent template uses `pkiCert`, which **caches** the
   90-day leaf and re-asserts the same serial on restart (removing `bundle.pem` doesn't help — the
   re-render produces the same cached cert, so the split command never fires). Fixed: issue a fresh
   leaf directly via the node's **own** Vault identity (`/run/nexus-vault-agent/token` + the on-node
   `vault` CLI → `pki_int/issue/redis-server`), parse the JSON in the AOT binary (`JsonDocument`,
   reflection-free), write `server.crt`/`server.key`/`bundle.pem`, reload `nexus-redis`. SSH-shell-out
   only — no managed Vault driver (ADR-0024). *Caveat:* the on-node Agent will re-assert its cached
   cert on its next render; persistent rotation needs the Agent's `pkiCert` cache refreshed (infra
   concern — handbook §3.3).

## scale-out provisioning model (ADR-0010)

Apply-on-demand, unbounded: `scale-out add` discovers a provisioned-but-unjoined reachable redis
node (a freshly-applied growth node, or one freed by a prior `scale-out remove`) and joins it with
the chosen `--role`. New nodes beyond the existing pool are minted by the proven IaC graph
(`oltp-redis.ps1 apply -Vars redis_extra_count=N` — the one-time per-cluster growth var/range is the
v0.6.x IaC follow-up); the adapter never hand-rolls a clone. The remove→re-add cycle above
live-verifies the full cluster-membership machinery.
