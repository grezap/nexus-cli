## What shipped

`StarRocksAdapter` (`src/Nexus.Cli.Adapters/Cluster/StarRocksAdapter.cs`) implements all of
`IClusterAdapter` via SSH-shell-out to the on-node `mysql` client against an FE's MySQL-protocol query
port (`:9030`) — **no managed MySqlConnector/JDBC driver** (NetArchTest-enforced). It authenticates as
the dedicated `nexus-cluster-admin` StarRocks user (granted `cluster_admin`+`db_admin`+`user_admin`,
`DEFAULT ROLE ALL`, distinct from the built-in `root`); that password comes from **Vault KV**
(`nexus/analytics/starrocks/operator-password`) via `INexusVaultClient` (ADR-0011 model, unchanged
framework). Registered in `ClusterBootstrapper`. AOT win-x64 **25.03 MB / 30 MB** (+0.19 MB over
clickhouse); **71/71** tests.

## Auth-model decision (from a live probe)

StarRocks is **password-auth** — `root` *requires* a password over the MySQL wire (the no-password
probe returns "Access denied … using password: NO"), and that password lives in Vault KV. → reuse the
LOCKED Vault-KV operator-credential model. Two contract specifics, both captured from the infra read:
`--skip-ssl` is required (the deb13 MariaDB 11.8 client otherwise negotiates a TLS the FE query port
doesn't enforce), and `SHOW FRONTENDS`/`SHOW BACKENDS` report the **VMnet10 backplane** IP (mapped to
a node via vms.yaml's vmnet10). `MYSQL_PWD` carries the password (no argv exposure, no warning).

## Control surface (ADR-0015)

- **FE BDB-JE quorum** — `SHOW FRONTENDS\G` (1 LEADER + 2 FOLLOWER, dynamic election; the leader was
  observed on `sr-fe-follower-1`, not the bootstrap-named node). The metadata plane + the only
  cluster-wide leader.
- **BE** — `SHOW BACKENDS\G` (Alive + TabletNum); hold the tablet data (`DISTRIBUTED BY HASH BUCKETS`
  × `replication_num=3`). Sharded by tablet hash, no fixed named shards.

## Cold-rebuild proof — ⏳ PENDING operator consent

default = `C:/Program Files (x86)/…/vmrun.exe`) — the same trap retired for analytics-clickhouse at
v0.6.4. The clean path is a from-zero **cold-rebuild** (power off cleanly via the correct path →
destroy → variables.tf vmrun_path fix → apply → `smoke-0.G.6.ps1`), which bakes the correct path into
fresh state and proves the new `role-overlay-starrocks-operator-user.tf` + creds-seed v2 in the apply
graph. This is a destroy of shared infra → **gated on explicit operator consent**. When run, this
section flips to **✅ PROVEN** with fresh-cluster evidence + the verb matrix re-run GREEN + any
cold-rebuild-surfaced transients chronicled.
