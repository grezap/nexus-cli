## Auth-model + access decision (from the live probe)

The **first Windows cluster** — the access pattern differs fundamentally from the six Linux adapters.
Two planes (ADR-0016 §1):

- **WSFC / cluster-resource cmdlets** (`Get-Cluster*`, `Move-ClusterGroup`, `Get-IscsiSession`,
  `Stop/Start-ClusterResource`) run over **plain Windows-SSH** as the local `nexusadmin` — it carries
  cluster-admin rights on the *local* node. (The memory's "cluster RESOURCE cmdlets HANG" applies to the
  *schtasks domain-task* context, not plain SSH — confirmed live: `Move-ClusterGroup` works over plain
  SSH.) Every command is wrapped in `powershell -NoProfile -EncodedCommand <base64-UTF16>`.
- **T-SQL** against the FCI runs as the dedicated **`nexus-cluster-admin`** SQL login (sysadmin) — the
  LOCKED Vault-KV operator-credential model (ADR-0011), password ONLY in Vault KV
  `nexus/oltp/sqlserver/operator-password` via `INexusVaultClient`, carried by `$env:SQLCMDPASSWORD`. A
  SQL login authenticates on the wire regardless of the OS session, so the slow/fragile schtasks
  domain-task dance is **not needed**. The standalone AG replicas are Windows-auth-only, so the few
  direct-replica ops (`ALTER … FAILOVER` on the target, manual-seed RESTORE/SET HADR) use `-E` (local
  nexusadmin IS sysadmin on the replicas).

**ClusterId scheme:** two adapters over one vms.yaml cluster (per ADR-0024) — `sqlserver` (FCI) +
`sqlserver-ag` (AG), mirroring the Kafka per-cluster scheme.

## Bug caught by live-verify

**`SqlAgAdapter.ScaleOutAddAsync` used `SEEDING_MODE = AUTOMATIC`** — which **cannot work** in this
hybrid FCI+AG topology (caught live: `sql-ag-rep-2` was found drifted at session start —
CONNECTED but `NOT SYNCHRONIZING / NOT_HEALTHY`, `nexus_demo` absent, `sys.dm_hadr_automatic_seeding`
showing `current_state=FAILED, failure_state=Seeding`). The FCI primary's `nexus_demo` files live on the
shared iSCSI `S:\`; automatic seeding preserves the primary's file paths and tries to create
`S:\SQLData\nexus_demo.mdf` on a standalone replica that has only local `C:\`. **Fix → MANUAL seeding**
(path-agnostic, mirroring `role-overlay-ag-bootstrap.tf §6`): `ADD REPLICA SEEDING_MODE=MANUAL` → `JOIN`
→ full+log `BACKUP` on the FCI primary to local `C:\Windows\Temp` → **SFTP-ferry** the `.bak`/`.trn`
build-host-mediated (active FCI node → build host → replica) + `icacls` Everyone-read → `RESTORE … WITH
MOVE … NORECOVERY` + `RESTORE LOG … NORECOVERY` + `ALTER DATABASE … SET HADR AVAILABILITY GROUP`. A new
`ISshClient.DownloadBytesAsync` was added for the ferry. **The fix doubled as the repair** — running
`scale-out remove sqlserver-ag sql-ag-rep-2` then `scale-out add` restored the replica to
CONNECTED+HEALTHY, and `scale-out add` is now the named operator recovery command for a drifted secondary.
