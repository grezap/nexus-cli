# 0.L.2.1 — iceberg-pg catalog-DB failover fencing (live verification)

**Date:** 2026-07-08 · **Tier:** lakehouse (iceberg-pg catalog pair) · **Repos:** `nexus-infra-lakehouse` (infra overlay) + `nexus-cli` (`LakehouseAdapter.FailoverAsync`)

Closes the first pre-Phase-1 infra-hardening item: **lakehouse iceberg-pg failover fencing** — turns
`failover-test cluster lakehouse --direction iceberg-pg` from a graceful **N/A refusal** into a real
one-shot catalog-DB failover with automatic fence + re-seed (no split-brain), and makes a promoted
standby actually serve the Nessie catalog.

## The gap (diagnosed live before the change)

The 0.L.2 pair had two defects that made a VRRP cutover unsafe (why it was N/A):

1. **`pg_hba.conf` (`NEXUS-ICEBERG-HBA` block) existed only on the PRIMARY.** On Debian `pg_hba.conf`
   lives in `/etc/postgresql/17/main`, **not** in `PGDATA`, so `pg_basebackup` never copied it to the
   replica. A *promoted* standby therefore refused the `nessie` role → the catalog front door landed
   on a PG that Nessie could not use → crash-loop.
2. **No fence / re-seed of the demoted old primary.** `nopreempt` left the old primary running →
   split-brain (both nodes primary). Indeed the tier was found in exactly that state at session start:

```
iceberg-pg-1 (.149): in_recovery=f  VIP=1  HBA_block=1  streaming_standbys=0
iceberg-pg-2 (.150): in_recovery=f  VIP=0  HBA_block=0   <-- split-brain + missing HBA
```

## The fix

**Infra** (`nexus-infra-lakehouse/.../role-overlay-iceberg-pg-replication.tf`, trigger `pg_repl_v` 1→2):
- Write the `NEXUS-ICEBERG-HBA` block on **BOTH** nodes (a promoted standby now admits Nessie), reloaded.
- Install `/usr/local/sbin/nexus-iceberg-reseed.sh <src-backplane>` on both nodes: a **guarded** fence
  + `pg_basebackup -R` re-seed. Refuses if the node holds the VIP (never wipe a live primary), if the
  source is not a reachable primary, or if it is already a streaming standby (idempotent).
- Install `/etc/keepalived/nexus-iceberg-fence.sh` + wire keepalived **`notify_fault`** → a detached,
  best-effort self-heal reseed against the peer (covers an *unattended* PG crash).

**Adapter** (`LakehouseAdapter.FailoverAsync`, `--direction iceberg-pg`): mirrors RegistryAdapter's
registry-db cutover — stop keepalived on the VIP-holding primary → poll VIP move + standby promoted →
**deterministically** run the reseed helper on the old primary (the adapter holds the nexusadmin key
and reaches both nodes; no inter-node SSH) → restart keepalived (nopreempt) → report RTO + recovery.

## Verification (all GREEN)

### Infra apply (targeted replace of the one resource)
```
terraform apply -target=null_resource.iceberg_pg_replication  →  1 added, 1 destroyed
post: pg-1 in_recovery=f VIP=1 ; pg-2 in_recovery=t wal_recv=streaming  (split-brain FIXED)
      HBA_block=1 on BOTH ; reseed.sh + fence.sh installed on BOTH ; notify_fault in keepalived.conf
      bash -n reseed.sh = OK on both nodes
```

### Guard proof (SAFETY 1 — never wipe the live primary)
```
$ sudo /usr/local/sbin/nexus-iceberg-reseed.sh 192.168.10.150   # run ON the primary (holds VIP)
[iceberg-reseed] REFUSE: this node holds VIP 192.168.70.151 (it is the primary)  ; EXIT=3
post: still primary, still 1 streaming standby (nothing touched)
```

### Failover drill — 4 runs, both directions, all GREEN (~8.5s each; RTO ~2.3s)
| # | direction | result | post-state |
|---|-----------|--------|------------|
| A | .149 → .150 | GREEN, recovered | pg-2 primary+VIP; pg-1 streaming standby |
| B | .150 → .149 (failback) | GREEN, recovered | pg-1 primary+VIP; pg-2 streaming standby |
| C | .149 → .150 (Nessie live) | GREEN, recovered | pg-2 primary+VIP; pg-1 streaming standby |
| D | .150 → .149 (restore canonical) | GREEN, recovered | pg-1 primary+VIP; pg-2 streaming standby |

Every run: VIP moved, target promoted (`pg_is_in_recovery=f`), **old primary auto re-seeded** as a
streaming standby (`pg_stat_wal_receiver=streaming`), keepalived back — **never a split-brain**.

### Nessie stays served (the pg_hba fix, end-to-end)
- **Direct proof** — the `nessie` role connects over TLS (`sslmode=require`) to the *promoted* node .150:
  ```
  nessie-admitted-on-promoted-node 192.168.70.150/32 in_recovery=false
  ```
  (pre-fix this was refused — no `pg_hba` entry for `nessie` on pg-2.)
- **End-to-end** — after failover, `GET https://…:19120/api/v2/trees` → **HTTP 200** (branch list from
  the catalog DB), and `pg_stat_activity` on the new primary .150 then shows `nessie|192.168.70.147`
  → Nessie's pool reconnected through the VIP onto the promoted node.
