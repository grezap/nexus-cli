# 0.L.4.1 — registry-db datastore failover re-seed (live verification)

**Date:** 2026-07-08 · **Tier:** registry (registry-pg datastore pair) · **Repos:** `nexus-infra-registry`
(infra overlay) + `nexus-cli` (`RegistryAdapter.FailoverAsync`)

Closes pre-Phase-1 infra-hardening item 2 of 4: **registry-db re-seed** — the registry datastore VRRP
failover already promoted PG + re-mastered Redis, but left the demoted old primary a **second PG primary**
(split-brain by design; "the DR runbook re-seeds it via pg_basebackup"). Now the failover fences +
`pg_basebackup` re-seeds the old primary automatically. Reuses the iceberg-pg (0.L.2.1) pattern.

## The gap (diagnosed live before the change)

Same two defects as iceberg-pg had:

1. **`NEXUS-REGISTRY-HBA` block existed only on the PRIMARY** — `pg_hba.conf` is in `/etc`, not `PGDATA`,
   so `pg_basebackup` never copied it → a *promoted* standby refused the Harbor DB user.
2. **`demote.sh` (notify_backup) re-attached Redis but NOT PostgreSQL** → after a cutover the old primary
   stayed a second PG primary (split-brain).

The tier was found **live-split-brained** at session start:

```
registry-pg-1 (.117): in_recovery=f  VIP=0  HBA=1
registry-pg-2 (.118): in_recovery=f  VIP=1  HBA=0   <-- split-brain; VIP holder LACKS the HBA block
```

Both nodes held **identical** Harbor data (registry DB 11 MB, 49 tables, 1 project, 2 artifacts; WAL LSNs
within a few bytes — no divergent writes, Harbor app off), so the canonical re-seed (pg-1 as source) was
loss-free — verified by inspecting both DBs before touching anything.

## The fix

**Infra** (`nexus-infra-registry/.../role-overlay-registry-pg-replication.tf`, trigger `pg_repl_v` 1→2):
- `NEXUS-REGISTRY-HBA` block on **BOTH** nodes (promoted standby admits the Harbor DB user), reloaded.
- `/usr/local/sbin/nexus-registry-reseed.sh <src>` on both — guarded fence + `pg_basebackup -R` re-seed
  (refuses if it holds the VIP / source not a primary / already a streaming standby).
- `demote.sh` (notify_backup) now re-points Redis **and** runs the guarded reseed (detached) — self-heal.

**Adapter** (`RegistryAdapter.FailoverAsync`): after promotion, deterministically runs the reseed helper on
the old primary (→ streaming standby), then restarts keepalived. New `ReseedTimeout`.


### Failover drills — 2 runs, both directions, all GREEN (RTO ~1.3–3 s)
| # | direction | result | post-state |
|---|-----------|--------|------------|
| A | .117 → .118 | GREEN, recovered | pg-2 primary+VIP+`role:master`; pg-1 streaming standby+`role:slave` |
| B | .118 → .117 (failback) | GREEN, recovered | pg-1 primary+VIP+`role:master`; pg-2 streaming standby+`role:slave` |

Every run: VIP moved, PG promoted, **old primary auto re-seeded** as a streaming standby
(`pg_stat_wal_receiver=streaming`), its **Redis re-pointed to `slave`** — **never a split-brain**.
