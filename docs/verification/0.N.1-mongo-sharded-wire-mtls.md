# 0.N.1 — MongoDB sharded cluster wire mTLS + cert-rotate (live verification)

**Date:** 2026-07-10 · **Tier:** oltp / mongo-sharded (11 VMs) · **Repos:** `nexus-infra-vmware` (security PKI/AppRoles) + `nexus-infra-oltp` (TLS overlays + templates + smoke) + `nexus-cli` (`MongoShardedAdapter`)

Closes the fourth (final) pre-Phase-1 infra-hardening item: **0.N.1 mongo-sharded mTLS** — brings the
11-VM sharded MongoDB cluster (config RS ×3 + 2 shard RSes ×3 + 2 mongos) to **wire mTLS parity** with the
0.G.2 non-sharded mongo RS, and implements the `MongoShardedAdapter` `cert-rotate` verb (was N/A). Done as
an **11-VM cold-rebuild** (the session's one cold-rebuild) that succeeded in a single from-zero pass.

## The gap

The 0.N sharded cluster shipped keyFile-only (`clusterAuthMode: keyFile`, `authorization: enabled`) with
**no wire TLS** — every mongod/mongos accepted plaintext connections. `cert-rotate mongo-sharded` returned
a graceful N/A ("no TLS on the wire; mTLS is the 0.N.1 hardening"). The 0.G.2 mongo RS already had wire
mTLS; this closes the parity gap.

## The fix

### Security env — `nexus-infra-vmware/terraform/envs/security/` (3 new overlays)
- `role-overlay-vault-pki-mongo-sharded.tf` — a new **`mongo-sharded-server`** PKI role at `pki_int/`,
  `allowed_domains` covering all 11 sharded hostnames (`mongo-cfg-{1,2,3}`, `mongo-shard-{1,2}-{1,2,3}`,
  `mongo-mongos-{1,2}`) in bare + `.nexus.lab` + `.mongo.nexus.lab` forms + localhost; server+client EKU,
  90-day leaf TTL, rsa-4096. Separate from the 0.G.2 `mongo-server` role so the two clusters version
  independently.
- `role-overlay-vault-agent-mongo-sharded-policies.tf` + `-approles.tf` — 11 per-host policies (PKI issue +
  `nexus/data/oltp/mongo/keyfile` read + token self-mgmt) + 11 AppRoles + `vault-agent-oltp-mongo-sharded-
  <host>.json` sidecars. Applied via a **targeted apply** (3 added, 0 changed, 0 destroyed — leaving 9
  pre-existing drifted LDAP/PKI-root resources untouched).

### oltp-mongo-sharded env — `nexus-infra-oltp/terraform/envs/oltp-mongo-sharded/`
- **New** `role-overlay-mongo-vault-agents.tf` — a per-host Vault Agent (`nexus-vault-agent.service`) on all
  11 nodes (reads the new sidecars; installs the vault binary; AppRole auth → token sink).
- **New** `role-overlay-mongo-tls.tf` — template 70 renders the per-host leaf (`pkiCert
  pki_int/issue/mongo-sharded-server`, CN `<host>.mongo.nexus.lab`) → `mongo-tls-split.sh` → `server.pem`
  (leaf+PKCS#8 key) + `ca.crt` (intermediate+root). (Templates 71/72 dropped — the keyFile stays from the
  existing build-host `role-overlay-mongo-keyfile.tf`.)
- **Modified** `role-overlay-mongo-config.tf` — injects `net.tls` (`requireTLS` +
  `certificateKeyFile`/`CAFile`, `allowConnectionsWithoutCertificates: false`, `disabledProtocols
  TLS1_0,TLS1_1`) into BOTH the mongod (cfg/shard) and mongos config shapes when `var.enable_mongo_tls`;
  `depends_on` the TLS overlay so certs exist before mongod restarts with `requireTLS`. `clusterAuthMode`
  stays keyFile (member auth); TLS adds wire encryption only.
- **Modified** `role-overlay-mongo-rs-initiate.tf` + `role-overlay-mongo-add-shards.tf` — every `mongosh`
  invocation gains `--tls --tlsCAFile … --tlsCertificateKeyFile …` (folded into the `__system` + operator
  auth strings; terraform-gated on `enable_mongo_tls`).
- No template rebuild needed (mongod TLS is native; the vault binary is installed by the overlay).

### Software — `MongoShardedAdapter.cs`
- TLS constants + a `TlsArgs` const folded into `SysAuth`/`OperatorAuth` → every eval-based verb
  (status/health/topology/failover/scale/acl/restore-verify) now dials over TLS in one edit. `--ssl
  --sslCAFile … --sslPEMKeyFile …` added to the inline `mongodump`/`mongorestore`.
- `RotateCertAsync` implemented (was N/A stub): per node (config → shards → mongos), **force the node's own
  vault-agent to re-issue a fresh leaf** (rm bundle.pem → restart agent → wait for the `server.pem` serial
  to change — the durable Swarm/vitess pattern), then reload it **ONLINE** via `db.adminCommand(
  {rotateCertificates:1})` — **no restart, no shard re-election**. `+ParseRerender` (+3 tests).

### smoke — `smoke-0.N.ps1` §9 (Wire mTLS)
`$tlsArgs` folded into both auth strings (every check over TLS) + a new section: per-host leaf CN, ca.crt
chain depth, `requireTLS` rejects a non-TLS connection, and an mTLS ping succeeds.
